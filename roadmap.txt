DISTRIBUTED LOCKING SERVICE - STEP-BY-STEP IMPLEMENTATION ROADMAP

Core Architecture: Spring Boot MVC REST API Architecture.
Client interacts with standard REST endpoints:
- POST /api/v1/locks/acquire -> Tries atomic Lua acquire. If free, returns ACQUIRED with token. If occupied, enqueues in Redis FIFO list and returns QUEUED.
- POST /api/v1/locks/release -> Releases token atomically, signals next waiter via targeted Redis Pub/Sub, and returns RELEASED.
- Key Expiry: Redis Key Expiration Listener (__keyevent@*__:expired) intercepts TTL expiration and automatically signals the next waiter.

================================================================================
END-TO-END WORKFLOW (SPRING MVC ARCHITECTURE):
================================================================================
1. Client calls: POST /api/v1/locks/acquire {"lockName": "order-123"}
2. Server executes Lua script (acquire_lock.lua) in Redis:
   - FAST PATH: If free, server immediately returns LockResponseDto(status=ACQUIRED, tokenId="uuid-111").
   - QUEUE FALLBACK: If occupied, server adds "uuid-111#timestamp" to Redis list (lock:queue:order-123)
     and returns LockResponseDto(status=QUEUED, tokenId="uuid-111").
3. When lock holder releases: POST /api/v1/locks/release {"lockName": "order-123", "tokenId": "token-A"}:
   - release_lock.lua verifies ownership token and deletes key.
   - LockManager.signalNext() publishes "ACQUIRE_NOW" to targeted channel "lock:notify:order-123:token-B".
4. TTL EXPIRATION SAFETY:
   - If current holder crashes or forgets to release, Redis TTL deletes the lock key.
   - RedisKeyExpirationListener intercepts __keyevent@*__:expired and triggers signalNext() to hand over to next waiter.
