DISTRIBUTED LOCKING SERVICE - STEP-BY-STEP IMPLEMENTATION ROADMAP

Core Architecture: Pattern A - High-Performance gRPC Server-Streaming (HTTP/2 multiplexed streaming).
The client sends AcquireLock(lock_name). If occupied, the connection stays open at zero CPU/thread cost.
The millisecond the lock is released, Redis Pub/Sub wakes up the server, which directly streams
LockEvent(ACQUIRED, token) back to the client. No client polling required.

================================================================================
END-TO-END WORKFLOW (PATTERN A - gRPC STREAMING):
================================================================================
1. Client initiates: rpc AcquireLock(lock_name="order-123") -> stream LockEvent
2. Server executes Lua script (acquire_lock.lua) in Redis.
   - FAST PATH: If free, server immediately streams LockEvent(status=ACQUIRED, token="uuid-111").
   - QUEUE FALLBACK: If occupied, server adds "uuid-111#timestamp" to Redis list (lock:queue:order-123),
     registers an internal listener on Redis channel 'lock:notify:order-123', and keeps the gRPC stream open.
3. Client does zero polling; connection is suspended at 0% CPU.
4. When lock holder releases via rpc ReleaseLock(lock_name="order-123", token="token-A"):
   - release_lock.lua deletes key AND publishes 'RELEASED' to Redis channel 'lock:notify:order-123'.
   - Server listener triggers immediately (sub-millisecond).
   - Server pops queue head, acquires lock atomically via Lua, and pushes LockEvent(status=ACQUIRED)
     to the waiting client stream!
5. TIMEOUT: If queue timeout (e.g. 10s) expires before the lock becomes free, server removes entry
   from queue, streams LockEvent(status=TIMEOUT), and closes the stream.
6. CLIENT DISCONNECT: If client cancels or disconnects early, server cleans up the queue entry
   so no abandoned tokens block the queue.
