DISTRIBUTED LOCKING SERVICE - STEP-BY-STEP IMPLEMENTATION ROADMAP

Core Architecture: Spring Boot MVC REST + SSE Architecture.
Client interacts with standard REST endpoints:
- GET /api/v1/locks/acquire?lockName=... (or POST /api/v1/locks/acquire) -> Server-Sent Events (SSE).
  - Fast Path: If free, sends ACQUIRED event and CLOSES connection immediately.
  - Queued Path: If occupied, enqueues in Redis FIFO list, sends QUEUED event, and KEEPS connection open.
  - Handover: When lock is released or expires, handover engine grants the lock, sends ACQUIRED event, and CLOSES connection.
  - Safety on Disconnect/Timeout: onTimeout/onError triggers internal revokeLock(lockName, tokenId) to clean up.
- POST /api/v1/locks/release {"lockName": "...", "tokenId": "..."} -> Releases token atomically, triggers handover engine to grant lock to next waiter.
- POST /api/v1/locks/revoke {"lockName": "...", "tokenId": "..."} -> If held, delegates to releaseLock internally; if queued, removes from queue.
- Key Expiry: Redis Key Expiration Listener (__keyevent@*__:expired) intercepts TTL expiration and automatically triggers queue handover.

================================================================================
END-TO-END WORKFLOW (SSE STREAMING ARCHITECTURE):
================================================================================
1. Client connects to: GET /api/v1/locks/acquire?lockName=order-123
2. Server checks lock availability via acquire_lock.lua:
   - FAST PATH: If free, server sends event "ACQUIRED" with tokenId, and immediately closes connection.
   - QUEUED PATH: If occupied, server enqueues "tokenId#timestamp" into lock:queue:order-123 via enqueue_lock.lua,
     sends event "QUEUED", and keeps connection open at 0% CPU.
3. When lock holder calls: POST /api/v1/locks/release {"lockName": "order-123", "tokenId": "..."}:
   - release_lock.lua verifies ownership token and deletes key.
   - Server triggers queueLockAcquire (queue_lock_acquire.lua):
     - Cleans expired entries at queue head.
     - Atomically assigns lock to first valid waiter with pure tokenId.
     - Returns winning tokenId to server.
   - Server locates winner's open SseEmitter, sends event "ACQUIRED", and closes the connection!
4. TTL EXPIRATION SAFETY:
   - If current holder crashes or forgets to release, Redis TTL deletes the lock key.
   - RedisKeyExpirationListener intercepts __keyevent@*__:expired and triggers triggerQueueHandover(lockName).
5. CLIENT DISCONNECT / TIMEOUT SAFETY:
   - If client disconnects or wait timeout triggers, emitter onTimeout / onError calls revokeLock(lockName, tokenId) internally.
   - revoke_lock.lua removes the entry from the queue (or if lock was held, calls releaseLock internally).
